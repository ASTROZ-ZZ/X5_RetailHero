# X5 RetailHero 数据看板

## 打开看板

| 文件 | 用途 | 打开方式 |
| --- | --- | --- |
| `../results/reporting/X5_RetailHero_经营分析数据看板.html` | 可在 Mac 上离线查看的交互看板，包含数据与图表代码 | 双击文件，在常用浏览器打开 |
| `X5RetailHero.pbip` | 可编辑 Power BI 项目，包含五页报表和语义模型 | 在 Windows 的 Power BI Desktop 中打开 |
| `data/` | 看板使用的 16 张业务汇总表 | CSV 可由 Power BI、Excel 或 SQL 工具读取 |
| `data_manifest.json`、`validation/verification.json` | 数据来源指纹与数值核验结果 | 文本编辑器打开 |

Power BI 项目使用随文件保存的数据，不需要先配置原始 CSV 路径。**本机是 Mac，尚未在 Windows Power BI Desktop 中打开、刷新并检查最终渲染**；如需正式发布，请先完成这一步。浏览器版本是独立交互实现，便于立即查看和演示，不是 Power BI 页面截图。

## 页面和筛选

| 页面 | 主要内容 | 筛选范围 |
| --- | --- | --- |
| 01 经营总览 | 客户规模、客群贡献、短信组间差异、保留集策略比较 | 固定项目口径 |
| 02 客户价值与复购 | 客群经营指标、购买近期程度、首次观察批次复购 | 客群、购买近期程度；Cohort 独立展示固定训练样本 |
| 03 消费趋势与门店 | 每日消费、订单量、门店表现 | 日期、匿名门店编号、客群 |
| 04 短信营销效果 | 短信组与对照组购买率、分群差异及 95% 区间 | 客群；汇总率由所选分群人数重新计算 |
| 05 选客策略与优化 | 策略效果、直接基线对比、覆盖曲线、重复验证 | 评估阶段；浏览器版验证集支持覆盖比例选择 |

浏览器版将训练样本全期消费额前 20 个匿名门店单独列出，其余门店合并为“其他门店”。合并前后订单和消费总量相等。Power BI 项目及 `OrdersDaily.csv` 保留全部匿名门店。门店没有地理信息，未制作地图。

## 核心指标口径

- 客户经营、门店与订单页面：固定训练集 120,022 名客户，历史订单 2,411,872 笔，历史消费额 1,033,847,003.72 源数据单位。订单以 `(client_id, transaction_id)` 识别，避免不同客户复用的交易编号被合并。
- 全量历史 400,162 名客户只作项目背景；营销实验、开发集、验证集、独立保留集各自使用其分析阶段的人群，不混作同一筛选总体。
- “购买率差”单位是**百分点**：短信组购买率减对照组购买率，或两种选客策略相应的购买率差之差。它不是相对提升百分比，也不能直接解释为利润。
- 独立保留集仅检验预先确定的 30% 覆盖比例：候选模型比随机选客高约 **0.29 个百分点**，95% 区间约 **-1.78 至 +2.37 个百分点**，优势尚未确认。其相对 RFM 的差异单独列示。
- 新增行为信息的开发集平均改善约 0.02 个百分点，不足以替换原模型。开发集重复交叉验证结果不能代替新的独立试验。
- Cohort 以数据窗口内“首次观察购买月份”划分，并非真实入会月份；首尾不完整月份或尚不可观察的月份保留空白。
- 缺少短信、优惠、毛利等成本信息，因此没有报告真实 ROI、利润或实际投放收益。官方待评客户的预测已输出，但没有对应真实购买结果，不能当作实际效果。

## 复现与核验

已交付的看板无需重新运行。若要从分析结果重新生成，在项目根目录依次运行：

```bash
python PowerBI/tools/prepare_data.py
python PowerBI/tools/build_powerbi.py
python PowerBI/tools/build_browser.py
python PowerBI/tools/verify_dashboard.py
node PowerBI/tools/test_logic.cjs
```

`prepare_data.py` 使用 `tools/aggregate.sql` 将训练订单按交易日期、门店和客群汇总，并用整数分核对金额；临时 SQLite 数据库在运行结束后删除。重新生成需要 `results/02_customer_analysis/tables/training_orders.csv.gz` 等已有阶段结果及足够磁盘空间。`build_browser.py` 需要 Pandas；`verify_dashboard.py` 需要 `jsonschema`。最后一项是离线 JavaScript 逻辑检查，**不等同于浏览器视觉验收**。

当前核验：16 张数据表、5 页原生报表、51 个视觉对象、62 份报表 JSON 的本地官方结构校验均通过；订单数和金额与原项目对齐。核验明细见 `validation/verification.json`，字段口径与源文件哈希见 `data_manifest.json`。

标题采用黑体、正文采用宋体，英文与数值采用 Times New Roman；整体使用紫色与黄色。显示效果会受到系统是否安装对应字体的影响。
