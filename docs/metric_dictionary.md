# 业务目标与指标口径

来源：本目录 `任务需求.md` 及本地六张 CSV。此文件定义本项目实施口径，不将自行选择的划分、模型或统计约定称为官方规定。

## 业务目标与基本粒度

目标：识别短信能够带来额外购买转化的客户，在给定触达比例下优先触达。购买概率与短信增量分别评价。

客户单位为 `client_id`；历史购买明细单位为商品行；交易单位按 `(client_id, transaction_id)`。全量检查发现 28 个 transaction_id 跨客户复用，不能单独作为全局主键。组合键内仍须检查时间、门店与交易金额一致性。商品维度按 `product_id` 多对一关联。不能把商品行数当作订单数。

原始 ID 一律以字符串读取。原始时间时区未注明，不转换为北京时间。精确触达日、结果观察窗口和随机化协议尚需来源证据补充；当前仅依任务说明将 purchases 视为营销前记录。

## 用户分析指标（第二阶段）

| 指标 | 计算口径 | 边界 |
|---|---|---|
| 购买次数 F | 窗口内不同客户＋交易编号组合数 | 不使用商品行数 |
| 消费金额 M | 交易级 purchase_sum 累计 | 确认交易内一致后每笔仅计一次 |
| 最近购买间隔 R | 参考日减末次购买日，单位天 | 可使用历史末日后一日为分析参考日，明确为假设；无历史单独标记 |
| 客单价 | 交易级消费金额 / 交易数 | 无交易时不可用，不伪装为真实零客单价 |
| 复购间隔 | 同客户相邻不同购买日期的天数 | 同日多单不作为跨日复购；只有一次购买无法估计 |
| 品类偏好 | 用户各品类商品行数量或经确认的行金额占比 | 先明确分母和商品字段语义；不可分配重复的整单金额到每条商品行 |
| 高价值客户 | train 内预先确定的 F、M 分位数分层 | 表述为观察期价值，不能等同生命周期价值 |
| Cohort 留存 | 观察窗口首次购买月份为 cohort；第 k 月再次购买客户 / 有足够观察期的 cohort 客户 | 不是注册留存；处理左截断和右删失，未到观察月记不可用而非 0 |

第二阶段在固定训练集上计算。R 的参考日取历史结束后的第一天（2019-03-19），实际短信触达日期仍待核实。复购指标先取每位客户相邻购买日间隔的中位数，同日多单只记为一个购买日。

分群要求频次与金额都达到训练集各自的上四分位阈值才算高价值，再根据最近购买间隔区分两类高价值客户。其余客户根据最近购买间隔的上下四分位分为近期活跃、低近期活跃和其他客户。等于阈值的客户一并纳入。实际阈值已记录在第二阶段 `analysis_summary.json`。

二级品类的主口径为商品明细行占比，同时提供正数量占比。零数量行计入出现次数，对数量汇总贡献为零。观察窗口首尾部分月份和窗口外月份不发布整月 Cohort 复购率。

## 实验指标（第三阶段）

- 处理组购买率：处理组 `target=1` 客户数 / 处理组客户数。
- 对照组购买率：对照组 `target=1` 客户数 / 对照组客户数。
- 绝对增量转化：处理组购买率减对照组购买率，单位为概率差，展示时使用百分点。
- ATE：在实验分配和识别条件成立时，上述差值估计平均处理效应；数据差值本身不能证明随机化。
- 不确定性：独立客户两比例差的 95% 置信区间；分组样本过小时提示估计不稳定。预设分层，探索性多重比较需说明。
- HTE/CATE：按营销前特征预设群体报告效应差异、样本量与置信区间；模型个体分数不能验证为个人真实效应。

第三阶段在固定训练集内采用非合并方差的两比例差区间。五个 RFM 客群的组内检验采用 Holm 校正。另用逆方差加权 Q 检验五群的购买率差是否相同，并单独对比「高价值待唤醒」与「高价值活跃」的购买率差。

## 模型与策略评价

主指标为 Uplift@30%，按任务需求的官方文字口径实现本地版本：

1. 预测分数从高到低排序；分数相同按 `client_id` 升序，以确保确定性。
2. 本地约定取 `floor(0.30 × N)` 位客户，至少需同时包含处理和对照客户，否则指标不可用。
3. 选中人群的处理组购买率减对照组购买率。

取整与并列处理为本地约定，正式声称复现官方评分前必须再核对官方基线代码。不同划分不直接比较成绩。

补充指标：多触达比例的增量转化、Uplift 曲线、Qini/AUUC。实现时需保存公式、归一化、随机基线及积分方法，避免不同库的同名指标直接混用。普通购买模型的 AUC 仅作为辅助诊断。

利润情景：触达人数 ×（该人群的估计增量购买率 × 每次增量购买的假设毛利 − 单次短信成本）。仅在明确成本与毛利假设时计算，不把模拟利润称为实际业务收益。

## 划分与预测交付

从 `uplift_train` 按客户划分 train/validation/holdout，分层变量为 `treatment_flg × target`，比例 60/20/20，SHA256 稳定排序；种子标识 20261116。分层取整可能带来数人差异。

客户探索与可学习预处理只使用 train；validation 用于选择模型及策略；holdout 只在选择完成后评价。一次性结构完整性、缺失和时间边界检查可覆盖全量，但不据 holdout 结果设计特征或调参。

`treatment_flg` 是处理指示，不是结果标签。S-Learner 可将它作为处理输入；T-Learner 用于分组拟合；在策略评分时比较两种处理状态。`target` 不得作为特征；提交样例的 `uplift` 不作训练标签。

最终输出两列 `client_id,uplift`，客户集合与官方测试列表完全一致，无重复、无缺失、分数有限，顺序优先与测试列表一致。官方测试无标签，只能校验格式与覆盖，无法计算其真实成绩。
